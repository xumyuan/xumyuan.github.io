CaptureSource ​

引擎默认的Capture Source的类型如下：

cpp
// EngineTypes.h line (L364 - 380)
/** Specifies which component of the scene rendering should be output to the final render target. */
UENUM()
enum ESceneCaptureSource 
{ 
	SCS_SceneColorHDR UMETA(DisplayName="SceneColor (HDR) in RGB, Inv Opacity in A"),
	SCS_SceneColorHDRNoAlpha UMETA(DisplayName="SceneColor (HDR) in RGB, any(Color.rgb) in A"),
	SCS_FinalColorLDR UMETA(DisplayName="Final Color (LDR) in RGB"),
	SCS_SceneColorSceneDepth UMETA(DisplayName="SceneColor (HDR) in RGB, SceneDepth in A"),
	SCS_SceneDepth UMETA(DisplayName="SceneDepth in R"),
	SCS_DeviceDepth UMETA(DisplayName = "DeviceDepth in RGB"),
	SCS_Normal UMETA(DisplayName="Normal in RGB (Deferred Renderer only)"),
	SCS_BaseColor UMETA(DisplayName = "BaseColor in RGB (Deferred Renderer only)"),
	SCS_FinalColorHDR UMETA(DisplayName = "Final Color (HDR) in Linear sRGB gamut"),
	SCS_FinalToneCurveHDR UMETA(DisplayName = "Final Color (with tone curve) in Linear sRGB gamut"),
};

各个取值对应解释如下：

  1. SCS_SceneColorHDR —— 线性HDR的SceneColor，Alpha通道存的反向的不透明度（1 = 完全透明，0 = 完全不透明）。注释里明说了这是故意不翻转的，为的是能反复往同一张贴图上 capture 并正确合成；美术要拿前景 opacity 得自己 1-a。注意 Alpha 通道有意义的前提是工程开了 r.PostProcessing.PropagateAlpha，否则那个 A 是垃圾值。

这里把存的反向透明度理解成透射度即可 透射度可以做简单的乘法累积，比不透明度的积累要更方便，计算方案如下： 叠 N 层半透明后：

A=∏i=1N(1−opacityi)

简单的解释就是第一次绘制了0.2透明度的东西，就只剩下0.8了第二次继续绘制0.4透明度的，就剩下0.8*（1-0.4）了。AfterDOF 独立 Color RT 的 Alpha 也是这种透射度，合成时 Scene * A * Modulate + Color，见 半透明渲染。

  1. SCS_SceneColorHDRNoAlpha —— 同样的 RGB，Alpha 硬写 0。DisplayName 里写的 any(Color.rgb) 是老实现的遗留，当前代码就是 0。
  2. SCS_SceneColorSceneDepth —— RGB 是 SceneColor，A 是线性深度（ConvertFromDeviceZ 之后的值，单位是世界单位/厘米，可以到几万）。RT 必须是浮点格式，RGBA8 会直接爆掉。
  3. SCS_DeviceDepth —— 注意它和上面两个不是一回事：写的是 1 - DeviceZ（因为 UE 是 reversed-Z），并且用 EncodeFloatRGBA 把这个 [0,1] 浮点打包成 RGBA 四个字节。所以它是专门给 8bit RT 用的，你要在材质里用 dot(RGBA, float4(1, 1/255, 1/65025, 1/16581375)) 解回来。它是非线性的（透视深度分布），近处精度高。
  4. SCS_Normal —— 从 GBufferA 取世界空间法线，直接输出 [-1,1] 范围，*不做 0.5+0.5 编码，所以 RT 必须是有符号浮点，RGBA8 会把负半轴全砍掉。仅延迟渲染可用。
  5. SCS_BaseColor —— GBufferC 的 BaseColor，纯反照率，不含任何光照。仅延迟渲染可用。
  6. SCS_FinalColorLDR —— 走 device 0，LinearToSrgb 编码后写进 8bit RT。值被 tone curve 压到 [0,1] 并且带 sRGB gamma。
  7. SCS_FinalColorHDR —— 跳过 FilmToneMap，输出 GradedColor——线性 sRGB 色域，包含曝光、Bloom、色彩校正/grading，但不含 tone curve、不含 gamma，值可以远大于 1。
  8. SCS_FinalToneCurveHDR —— 应用了 tone curve（FilmColorNoGamma），但仍然是线性、不做 device gamma 编码。适合"我想要电影感的颜色，但还要在后面继续做线性混合"的场景。

最后三个带Final的就是走完了完整的后处理，其余的没有 TAA、没有 Bloom、没有 DOF、没有自动曝光、没有 tonemap、没有 color grading。渲染完 BasePass 拿到 SceneColor/GBuffer 后，用一个全屏 pass 把对应通道拷进 RT
