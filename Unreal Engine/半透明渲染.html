UE 半透明渲染（4.27 Deferred） ​

本文讨论 UE 4.27.2 桌面 Deferred 管线中的常规光栅半透明路径。Mobile、光线追踪半透明和后续 UE5 版本有各自的实现，不能直接套用这里的 Pass 与排序结论。

通用的 Alpha 混合、深度写入和交叉排序原理见 透明渲染。本文重点解释这些原理在 UE 中如何落实：材质决定混合方式和光照方式，可见性阶段决定进入哪些 MeshPass，各 Pass 分别排序、绘制，最后按约定合成到场景。

1. 先看半透明在一帧中的位置 ​

UE 的 Deferred 管线并不是所有物体都走延迟光照。常规半透明不把自己的多层表面写进不透明 GBuffer，而是在不透明场景已经完成光照后，用透明材质自己的 Shader 着色并合成。

text
不透明 / Masked 几何
    -> GBuffer 与不透明深度
    -> 延迟光照，准备半透明光照体积
    -> 大气、雾等场景处理
    -> 绘制半透明
         Standard：通常直接混入 SceneColor
         AfterDOF：写独立颜色缓冲，暂不混入 SceneColor
         AfterDOFModulate：写独立滤色缓冲
    -> 后续 Distortion、透明速度等相关 Pass（按配置执行）
    -> 后处理：对 SceneColor 做景深，并在相应阶段合成独立半透明

这是理解主路径的简化顺序。水下半透明等特殊路径会提前到 SingleLayerWater 之前；完整帧结构见 UE基础渲染管线。

AfterDOF 主要描述合成时机，不等于所有透明几何都等到景深结束后才开始绘制。 几何可以先画到独立 RT，等背景完成景深后再合成。

透明颜色 Pass 通常开启深度测试、关闭深度写入：用不透明深度挡住墙后的透明片元，同时允许多层透明贡献颜色。UE 常用比较函数 CF_DepthNearOrEqual；启用材质的 Disable Depth Test 后可改为 CF_Always，也就失去了这层不透明遮挡。Custom Depth、速度等额外 Pass 需要分别看自己的状态。

关于 GBuffer 为什么不能直接混合透明材质，见 延迟渲染如何处理半透明。

2. 材质先决定怎样混合 ​

Blend Mode 回答的是：当前片元的输出怎样改变已经存在的目标颜色？ 它与 Lighting Mode、Render After DOF 是不同的选择。

在本文讨论的常规表面材质中，Opaque 和 Masked 走不透明路径；IsTranslucentBlendMode 用于识别其余相关透明混合模式。Masked 是阈值裁剪：片元被丢弃或作为不透明表面保留，不表达连续半透明。

以下只列常见 RGB 混合关系，具体状态还会随目标 Pass 和着色路径变化。S 表示 Shader 输出的源颜色，D 表示目标颜色，a 表示源 alpha。

Blend Mode常见 RGB 合成用途与注意点
TranslucentS * a + D * (1 - a)普通半透明；需要正确的前后顺序
AdditiveS + D光晕、火焰；Shader 可先把材质 Opacity 乘进 S，不能因硬件系数为 One 就认为 Opacity 无效
ModulateS * D背景滤色；只表达乘色，不独立增加反射高光
AlphaCompositeS + D * (1 - a)预乘 alpha；源 RGB 已含相应权重，不应重复乘 alpha
AlphaHoldoutD * (1 - a)衰减当前目标颜色，用于受支持的 holdout 合成；不是让不透明几何的深度消失

纯加法层之间在理想线性累加下与顺序无关，但它们和普通 Alpha 混合层交错时仍可能有顺序差异。例如先加上的光晕会被后画的烟雾衰减，最后加上的则不会。

Thin Translucent 是 Shading Model，不是上表中的另一个 Blend Mode。 它需要同时表达表面的加色贡献与背景的彩色透射，可抽象为：

text
Final = SurfaceContribution + ColoredTransmittance * Background

能够直接访问真实背景的路径可通过 Dual Source Blend 表达这类关系；Separate Translucency 路径则需要拆开保存相应贡献，见下文。Thin Translucent 通常配合 Translucent Blend Mode 和 Surface ForwardShading 使用。

普通 alpha、预乘 alpha 的计算示例见 Alpha Blend 与绘制顺序。

3. 为什么要分成不同的半透明 Pass ​

景深决定什么时候合成 ​

如果半透明已经混进 SceneColor，后续景深会把它和背景一起处理。烟雾、特效是否应该被这次景深模糊，便成为划分透明 Pass 的一个依据。

UE 4.27 材质中的 Render After DOF 对应 bEnableSeparateTranslucency。允许 Separate Translucency 时，主要分为下面几类：

类别MeshPass主要进入条件目标与合成时机
StandardTranslucencyStandard不启用 Render After DOF通常直接写 SceneColor，参与后续景深；降分辨率路径可先写独立 RT 再立即合成
AfterDOFTranslucencyAfterDOF启用 Render After DOF，且具有颜色贡献写独立 Color RT，在景深之后或其重组阶段合成
AfterDOFModulateTranslucencyAfterDOFModulateAfterDOF 中的 Modulate / DualBlend 乘色贡献写独立 Modulate RT，与独立颜色一起合成
AllTranslucencyAll不允许 AfterDOF 分离路径合并到单一透明 Pass 中处理

因此，三个 Pass 并不一定对应三组互不相交的物体。同一材质如果同时具有加色和乘色贡献，可以参与两个 Pass。纯 Modulate 则不需要向独立颜色 RT 写入加色贡献。

RenderTranslucency 中可以把调度理解为：

text
AllowTranslucencyAfterDOF() 为真：
    Standard -> AfterDOF -> AfterDOFModulate
否则：
    All

这个分支判断的是当前视图与配置是否允许分离路径，不能只根据本帧是否看到了景深模糊来推断。材质开关、Separate Translucency 配置和后处理能力要一起看。

采样背景与普通混合是两件事 ​

普通 Alpha Blend 由混合单元读取目标颜色，不要求透明 Shader 自己采样 SceneColor。材质需要 SceneColor 采样时，相关路径通过 AddCopySceneColorPass 等准备副本，避免将同一资源同时作为普通采样纹理和正在写入的渲染目标。

折射还涉及 Distortion 等处理，不能把所有折射都理解成普通 Alpha Blend 中的一次 SceneColor 采样。SceneColor 副本只记录复制时已有的内容，也不会自动提供所有透明层的完整颜色与深度，因此不等于支持任意多层玻璃互相折射。

4. 独立半透明缓冲到底存了什么 ​

Color 的 Alpha 保存剩余透射率 ​

AfterDOF 不能预先把背景烘进自己的颜色，因为真正要合成的背景还需要做景深。它需要记录“透明层自身贡献多少颜色”和“背景还应保留多少”。

先只考虑普通 Translucent，记 C 为已累积的颜色贡献，T 为背景剩余透射率。按照从后往前的顺序处理每层：

text
初始：C = 0，T = 1

新片元颜色为 S，alpha 为 a：
    C = S * a + C * (1 - a)
    T = T * (1 - a)

最终：Final = C + Background * T

因此，独立 Color RT 的 RGB 是已经混合过的颜色贡献，不是把所有原始颜色简单相加；Alpha 保存的是 T，也不是直觉中的累计不透明度 1 - T。

例如两层 alpha 分别为 0.2 和 0.4，背景剩余比例是 0.8 * 0.6 = 0.48。这与 SceneCapture 中 Inv Opacity 的概念相通，但不同输出目标的 Alpha 含义仍需分别确认。

为什么还要一张 Modulate RT ​

一个标量 T 只能同等衰减 RGB 三个通道，不能同时表达“红色透过 20%，绿色透过 70%，蓝色透过 20%”。滤色需要额外保存一个 RGB 乘数 M。

项目Separate ColorSeparate Modulate
保存内容RGB 为颜色贡献 C，Alpha 为透射率 TRGB 为滤色乘数 M
空缓冲的值(0, 0, 0, 1)RGB 为 (1, 1, 1)
常见格式PF_FloatRGBAPF_FloatR11G11B10
对应默认纹理BlackAlphaOneDummyWhiteDummy

这种布局中，加色从黑开始，透射率和滤色从 1 开始，空缓冲不会改变背景。不是任意一种 RT 都无法存这些信息，而是当前布局需要同时容纳 RGB 颜色、标量透射率和 RGB 滤色数据。

ComposeSeparateTranslucency.usf 以及相应 DOF 重组路径的核心关系可以概括为：

text
Final = Scene * Separate.a * Modulate.rgb + Separate.rgb
      = Scene * T * M + C

普通半透明不贡献额外滤色时，M = 1。例如取 T = 1，背景墙颜色 (1.0, 0.8, 0.6)、滤色 (0.2, 0.7, 0.2)、表面高光 (0.3, 0.3, 0.3)：

text
背景滤色：Scene * M     = (0.2, 0.56, 0.12)
再加高光：Scene * M + C = (0.5, 0.86, 0.42)

在这里讨论的 AfterDOF 分离路径中，Thin Translucent / DualBlend 材质可将同一网格分别提交给颜色和乘色 Pass。不能由此推导所有 Thin Translucent 在所有管线中都会绘制两遍。

两张 RT 解决的是贡献的存储与合成，并没有保存每个像素的完整透明层列表，所以 Separate Translucency 不是 OIT。不同 Pass 的贡献也不能靠一个物体级排序键恢复任意交错关系。

5. 网格怎样进入这些 Pass ​

这一段要分清两个步骤：先确定网格属于哪些 Pass，再由对应的 Mesh Processor 构造绘制命令。 完整机制见 渲染机制。

text
材质属性
    -> Material Relevance：声明需要哪些透明路径
    -> SceneVisibility：将可见网格登记到对应 MeshPass
    -> 对应的 FBasePassMeshProcessor：过滤并构建 DrawCommand
    -> 按当前视图更新排序键
    -> 排序与提交

在允许分离的路径中，相关 Relevance 与 Pass 的对应关系是：

Material Relevance对应类别
bNormalTranslucencyStandard
bSeparateTranslucencyAfterDOF 颜色
bSeparateTranslucencyModulateAfterDOF 乘色

这些信息由 UMaterialInterface 的材质 Relevance 计算路径结合 Blend Mode、bEnableSeparateTranslucency、DualBlend 等条件生成；不允许分离时则使用 All 路径。

SceneVisibility.cpp 中，静态 Mesh 通过 DrawCommandPacket.AddCommandsForMesh(..., EMeshPass::Translucency*) 登记，动态 Mesh 通过 PassMask.Set(...) 标记所需 Pass。需要颜色和乘色两路的网格可以被登记到两个列表。旁边的 TranslucentPrimCount.Add 用于统计与判断是否需要渲染，不负责构造 DrawCommand。

FBasePassMeshProcessor 在构造时已经确定自己的 TranslucencyPassType，因此 TryAddMeshBatch 中的 switch 主要回答“当前 Processor 是否接收这条 Mesh”，不能把它当成将网格分发给所有 Pass 的入口。对应注册入口包括 RegisterTranslucencyStandardPass、AfterDOF 和 AfterDOFModulate。

还要区分 静态 Mesh 数据与缓存好的 MeshDrawCommand。这里的半透明 MeshPass 没有启用 CachedMeshCommands 时，静态 Mesh 也会通过 DynamicBuildRequests 请求本帧构造命令；不能看到静态模型就认定其透明命令无需重建。

6. 排序 ​

按绘制项排序，并非逐像素排序 ​

UE 4.27 常规光栅透明路径没有通用 OIT，也不自动对任意透明 Mesh 做逐三角形排序。每个透明 Pass 维护自己的绘制列表，各 Pass 之间不进行一次统一的全局深度排序。

UpdateTranslucentMeshSortKeys 会结合当前 View 和 Primitive 信息更新排序键。64 位键可概括为：

text
Priority (16 bit) | Distance (32 bit) | MeshIdInPrimitive (16 bit)
字段作用
Priority来自 TranslucencySortPriority；优先级越大通常越晚画，因此会覆盖较低优先级的透明贡献
Distance根据当前相机、Primitive Bounds 中心和排序策略生成；相同优先级下，通常让远处先画
MeshIdInPrimitive用于同一 Primitive 内绘制项的稳定次序，不代表真实的逐三角形深度

Priority 和 MeshId 在建立排序键时提供，Distance 随视图更新。这里不应把前两者笼统称为“缓存阶段设置”，因为透明命令本身可能就在本帧重建。

r.TranslucentSortPolicy 对应的常见策略为：

值策略排序依据
0SortByDistance相机到 Bounds 中心的距离，常见于 3D 场景
1SortByProjectedZ沿相机观察方向的投影深度
2SortAlongAxis沿配置轴的投影，适合固定排序方向的场景

TranslucencySortDistanceOffset 可以偏移排序用的距离，但不移动几何，也不改变其真实深度。Priority 和 Offset 都只是在调整提交顺序。

交叉为什么仍然会错 ​

一个大玻璃面片可能在屏幕左侧位于另一个物体前面，右侧却位于它后面。Bounds 中心只提供一个排序值，无法同时满足这两个像素的要求。拆分成多个 Section 也不自动获得正确的逐三角形深度排序。

Niagara / Cascade 可以在系统内部进行粒子排序，但系统内部的顺序不能自动解决粒子与外部透明网格之间的交叉。同样，AfterDOF 与 Standard 已分属不同合成阶段，提高 Sort Priority 不会让它们重新加入同一份全局排序列表。

工程上可以按问题性质选择：

情况可考虑的处理限制
前后层次固定的特效Priority 或 Distance Offset是针对固定关系的控制，不解决局部前后关系反转
少量相交的静态玻璃沿实际交叉关系拆分几何，再组织绘制随意拆成几个子网格不保证正确
适合纯加光的效果Additive会改变视觉模型，与其他 Alpha 层交错时仍需关注顺序
主要是镂空轮廓Masked，或适用时用 Dithered Opacity Mask抖动依赖时域积累，可能有噪点和拖影，不等于玻璃透射
粒子插进不透明地面材质 DepthFade柔化交线，不解决透明层之间的排序
必须准确保留复杂交叉层次评估自定义 OIT / 其他专用渲染路径需要额外实现与性能预算，不是上述排序参数能做到的

交叉示意、Depth Peeling、逐像素链表和 Weighted Blended OIT 的原理与取舍见 透明物体交叉如何处理。DepthFade 对应的通用思路见 Soft Particles。

7. 半透明的光照从哪里来 ​

“走前向透明 Pass”意味着透明片元用自己的材质完成着色，并不意味着每种透明材质都会逐像素重新遍历所有灯。UE 提供不同的 Translucency Lighting Mode，以适配烟雾、表面玻璃等不同需求。

Translucency Lighting Volume ​

常见体积光照路径先在灯光阶段通过 InjectTranslucentVolumeLighting 等处理把光照注入相机附近的 3D 纹理，再由透明 Shader 通过 GetTranslucencyVolumeLighting 等函数采样。

它使用 Inner / Outer 两级覆盖范围，每级保存 Ambient / Directional 等光照信息；常见默认维度为 64^3，可由 r.TranslucencyLightingVolumeDim 等配置调整。有限分辨率意味着细小光照与阴影会变模糊，覆盖范围越大，同样分辨率下的空间精度越低。维度翻倍时，每张体积纹理的体素数量约变为八倍。

Lighting Mode 的区别 ​

Lighting Mode光照方式与适用情况
Volumetric NonDirectional体积光照，不使用材质法线表达方向变化，适合较均匀的烟尘
Volumetric Directional利用方向性光照和法线表达变化，适合需要立体感的体积效果
Volumetric PerVertex 系列在顶点阶段求相关光照，再插值给像素；通常减少像素开销，但受网格密度影响
Surface TranslucencyVolume以表面材质方式使用低分辨率体积光照；直接光主要是漫反射，不能期待清晰的逐像素局部灯高光
Surface ForwardShading在表面逐像素计算前向直接光照，可得到局部灯高光；灯数、覆盖面积和重叠层数都会影响成本

Surface TranslucencyVolume 的限制不等于材质只能输出漫反射颜色；环境反射、自发光等仍需看相应材质与渲染路径。Thin Translucent 要表现表面高光和有色透射时，通常使用 Surface ForwardShading。

8. 遇到问题时先检查哪一层 ​

现象优先检查
透明物体和背景一起被景深模糊Render After DOF、Separate Translucency 是否生效，以及实际合成位置
调高排序优先级也没有达到预期遮挡关系两者是否属于不同 Pass，或是否存在局部交叉
玻璃缺少清晰的局部灯高光Lighting Mode 是否仍为 Surface TranslucencyVolume
染色玻璃只有亮度变化，没有分通道滤色是否需要 Thin Translucent，以及对应颜色 / 乘色路径是否启用
粒子与地面相交出现硬边DepthFade 以及可采样场景深度是否符合预期
透明物体穿墙显示Disable Depth Test 或其他覆盖了深度状态的设置
半透明开销高屏幕覆盖率、重叠层数、Shader 与光照复杂度，以及独立 RT 的分辨率和额外 Pass

拆到独立 RT 并不自动降低成本。低分辨率渲染可以节省部分像素开销，但还要支付 RT、采样、上采样和合成成本，也可能损失边缘与细节质量。
