Cocos粒子杂项暂存 ​

2D粒子类型分类 ​

cocos2d 粒子主要可以按两个正交的维度分类：运动状态 x 位置

运动状态 ​

按照运动状态可以分为 GRAVITY 和 RADIUS

GRAVITY：笛卡尔速度 + 牛顿积分 ​

速度存在 dir 里。每帧先累加速度，再积分位置：

radialDir     = normalize(pos)                 // 相对发射源；在原点则为 0
tangentialDir = (-radialDir.y, radialDir.x)    // 逆时针 90°
vel += (gravity + radialDir * radialAccel + tangentialDir * tangentialAccel) * dt
pos += vel * dt * yCoordFlipped
三个加速度：两套坐标系 ​
  • gravity：世界轴上的常向量，所有粒子同一方向（通常往下）。不依赖粒子在哪，一个数就够。
  • radialAccel / tangentialAccel：围着发射源的极坐标分解。方向依赖粒子位置，不能写成固定向量。
        tangential (-ry, rx) 逆时针
              ↑
              |
    发射源 ·--+--> radial (rx, ry) 沿「源→粒子」
              |
              某粒子
为什么是两个参数 ​

相对发射源，任意力都能拆成「沿半径」和「垂直半径」两个分量——这是 2D 力场的两个自由度，也是给美术的两个旋钮：

  • 径向：改离发射源的远近。正的往外推（爆炸），负的往里拉（Galaxy 收束）。
  • 切向：改绕发射源的角度，不直接改距离。有它才会转（Spiral）。

只留 gravity，所有粒子永远被推向同一方向，做不出「绕着喷口转」或「被吸回中心」；只留径向，只能胀缩，转不起来。三者叠起来，才覆盖烟 / 烟花 / 星系 / 螺旋。

两个标量对所有粒子共用，方向却每帧随粒子当前位置重算——飞到哪里，力就指向「源→粒子」或垂直于它。出生时写死一个 (ax, ay) 做不到：飞走之后那个向量还指着旧方向，中心吸、螺旋都会散掉。

实例与对比 ​

引擎里的现成例子就是按这两个旋钮配的：ParticleGalaxy 径向 -80 + 切向 80（往里收同时转）；ParticleFlower -60 / 15；ParticleSpiral -380 / 45（强吸、慢转，收成螺旋）。Fire / Smoke / Fireworks 两个都是 0，只靠出生 speed 和 gravity。

和 RADIUS 模式的差别：这里粒子仍有速度、有惯性，力只是在推它；RADIUS 每帧用 (r, θ) 重写位置，没有「飞过去被吸弯」这种惯性。GRAVITY 模式用两个标量换来的，是中心力场 + 牛顿积分可以叠在一起（星系还能再往下掉）。

RADIUS：极坐标 + 直接重算位置 ​

每颗粒子带着：

  • angle：弧度
  • degreesPerSecond：角速度（名字是度，存的是弧度/秒）
  • radius / deltaRadius：当前半径、每秒半径变化

每帧不积速度，直接重算位置：

angle  += ω * dt
radius += deltaRadius * dt
pos = (-cos(angle) * radius, -sin(angle) * radius * yCoordFlipped)

负号是 Particle Designer 约定。轨迹只能是「绕发射源的圆/螺线」：半径不变就是转圈，半径收到 0 就是往里卷。没有重力、没有切向这两个独立力。

两种状态不能混在一颗粒子上。SoA 里 modeA 和 modeB 数组都分配了，但 update 只进一个分支。要烟花往下掉用 GRAVITY；要法阵绕点转用 RADIUS。

位置：已出生粒子钉在哪 ​

模拟始终在发射源局部。位置类型回答的是另一件事：喷出来之后，发射器（或别人）跑了，已经活着的粒子跟不跟。

粒子自己该飞还是飞，只是「家」订在哪不同：FREE 订在世界上出生的那个点，后面三种订在某个节点上。

出生时记下 startPos（参考点），画的时候再取一次「当前参考点」，用两者的差去折 pos。GROUPED 记下了也不用。

类型出生 startPos发射器平移发射器旋转/缩放典型用法
FREE当时的世界坐标不管不跟（补偿掉了）拖尾、爆炸碎屑留在原地
RELATIVE节点 _position跟着不跟旋转挂在精灵上，要平移不要拧
TRACKTrack 节点局部跟 Track不跟旋转系统挂在 A，却跟着父节点 B
GROUPED写了不用跟着完整跟着绑在角色/武器上一起转

FREE：不跟 ​

烟已经喷到路上了，人走开，烟还留在原地继续飘。适合拖尾、爆炸碎屑。

发射器从世界点 W0 走到 W1。某粒子出生时 startPos = W0，局部 pos 是相对发射源的位移。画的时候把 W1 和 W0 都变到节点空间，差就是发射器这段时间的位移，从 pos 里减掉，粒子留在出生时的世界点附近（再加上它自己飞过的 pos 变化）。所以烟的尾巴留在走过的路上。

加速度不看 FREE。径向 / 切向每帧仍是 normalize(局部 pos)，力心永远是模拟原点 (0,0)，也就是发射器当前的局部原点。FREE 只改画：

画面世界位置 ≈ 出生时发射器世界点 W0 + 局部 pos

局部 pos 被吸向 0，画面上就是被吸向 W0（这颗粒子出生时喷口在哪），不是现在的 W1。各颗的 startPos 不同，看起来就像每颗自带一口「出生时钉住的井」。gravity 同样在局部轴上加，FREE 也不改它的算法。Fire / Smoke 径向切向常为 0，发射器走开只剩初速和重力，这个错位看不出来。GROUPED 没有这层折算，吸向 0 就是吸向现在的喷口。

RELATIVE：跟平移，不跟旋转 ​

喷口绑在角色身上，角色跑，烟团一起跑；角色转身，烟的形状不跟着拧。

newPos = pos - (currentRef - startPos)

currentRef - startPos 是参考点这一帧相对出生时的平移。减掉它，等于让局部 pos 跟着参考点平移。旋转、缩放不在这个减法里，所以发射器转了，粒子云的形状不跟着拧，只是整体挪地方。

头文件注释把 RELATIVE 说成 “attached to the world but follow emitter repositioning”，GROUPED 说成 “attached to the emitter”。差别是：RELATIVE 只补偿平移；GROUPED 把 pos 当节点局部坐标，Node 的 model-view 整套吃进去。

TRACK：跟平移，但参考另一个节点 ​

和 RELATIVE 一样只跟平移，但跟的不是发射器自己，是你指定的另一个节点。

currentRef 换成 Track 节点：粒子系统可以是角色的子节点（吃层级），运动跟随却绑在另一个节点上。_trackNode == null 时 TRACK 退化成 RELATIVE。

GROUPED：平移、旋转、缩放全跟 ​

死死粘在身上。跑也跟、转也跟、缩放也跟。Studio 里默认基本是这种。

newPos = pos，不做补偿。draw 时 Renderer 再乘节点 MV，平移旋转缩放全部作用在每个顶点上。角色转身 90°，整团粒子一起转。这就是「附着在发射器上」。

补充 ​

同一套 GRAVITY 烟，FREE 是走过留下一串，GROUPED 是烟团粘在角色脚上。同一套 RADIUS 转圈，FREE 是圈子钉在出生点的世界位置，GROUPED 是圈子跟着节点走、跟着转。

Studio 不读 plist 的 positionType。节点名含 _free 才是 FREE，否则 GROUPED。游戏里大多数 CSB 粒子其实是 GROUPED，不是引擎默认的 FREE。

位置类型不改变 pos 的积分，所以切 PositionType 不必重算运动；但必须在出生时就定好，因为 startPos 的空间（世界 / 节点 / Track）已经写进粒子里。中途改类型，旧粒子的 startPos 和新折法会对不上。
