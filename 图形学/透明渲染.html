透明渲染 ​

本文介绍透明渲染的通用原理。UE 4.27 Deferred 中的材质设置、半透明 Pass、独立缓冲合成和排序实现，见 UE 半透明渲染。

透明测试 ​

和深度测试的思路类似，剔除某些小于透明阈值的像素，实现某些位置完全透明，我们设定一个alpha阈值，当片元不满足条件（通常是小于阈值）就直接舍弃当作全透明，满足条件的片元就直接当作不透明物体进行处理。所以注意AlphaTest并没有实现真正的半透明效果。

混合透明效果 ​

将新渲染出来的图像和已存在的进行合并。

常用的混合模式有：

  • Blend Off 关闭混合处理。
  • Blend SrcFactor DstFactor 开启混合处理，自定义混合模式，将源颜色（当前片元着色器输出）和目标颜色（渲染目标中已存在的颜色）按照混合系数进行rgba四通道的加权混合。
  • Blend SrcFactor DstFactor,SrcFactorA DstFactorA 与上条类似，只不过分别计算rgb通道和alpha通道的混合。
  • BlendOp Op：指定混合运算，比如Add，Sub等（默认不写为Add）；这些算术混合运算不等同于按位逻辑操作。
  • BlendOp OpColor，OpAlpha：分别指定rgb通道和alpha通道的混合运算。

BlendOp 指定运算，Blend 指定混合系数；这里是 ShaderLab 风格的渲染状态声明，不是必须先执行 BlendOp 再执行 Blend 的命令序列。

Alpha Blend 与绘制顺序 ​

普通半透明常用 Blend SrcAlpha OneMinusSrcAlpha，在默认的 Add 运算下，RGB 结果为：

text
C_out = alpha_src * C_src + (1 - alpha_src) * C_dst

这里的 C_src 是当前片元完成光照后的颜色，C_dst 是此前已经画好的背景。计算应在线性颜色空间中进行。若输入已经预乘了 alpha，即 C_src_premul = alpha_src * C_src，则使用 Blend One OneMinusSrcAlpha，避免再乘一次 alpha。

若还需要将目标 alpha 留给后续合成使用，通常单独设置 alpha 的混合系数。例如非预乘 RGB 使用 Blend SrcAlpha OneMinusSrcAlpha, One OneMinusSrcAlpha，使 alpha_out = alpha_src + (1 - alpha_src) * alpha_dst。

Alpha 混合有顺序要求。例如黑色背景上，红色和蓝色两个面片的 alpha 都为 0.5：

  • 先画蓝色，再画红色，得到 (0.5, 0, 0.25)。
  • 先画红色，再画蓝色，得到 (0.25, 0, 0.5)。

因此通常先画不透明物体，再将半透明物体按距离从后往前画，让近处表面覆盖在已经混合好的远处颜色上。预乘 alpha 改变的是颜色表示，并不会消除这个顺序要求。

延迟渲染如何处理半透明 ​

为什么不能直接混合 GBuffer ​

延迟渲染的常规 GBuffer 在每个像素上只保存一层表面的法线、反照率、粗糙度等数据。深度测试会保留最近的表面，而半透明需要同时知道这个表面以及它后面的多层颜色。

不能简单地按照 alpha 把多层材质属性混进 GBuffer 再统一算光，因为光照计算通常是非线性的：先混合法线、粗糙度等属性再算一次光，不等于各层分别算光后混合颜色。单层 GBuffer 还会丢失各层的深度和遮挡次序。

所以“延迟渲染不支持半透明”通常指的是常规单层 GBuffer 路径不能直接表达多层半透明，并不是采用延迟渲染的引擎不能显示半透明。

常见流程：不透明走延迟，半透明走前向 ​

text
不透明 / Alpha Test 几何
    -> Geometry Pass：写 GBuffer 和不透明深度
    -> Lighting Pass：读取 GBuffer，得到不透明 SceneColor
    -> 半透明 Pass：保留不透明深度，前向着色，混合到 SceneColor
    -> 后续合成 / 后处理

具体做法：

  1. 先完成不透明渲染。得到已完成光照的 SceneColor，以及最近不透明表面的深度；背景或天空也应在依赖它的透明合成之前准备好。
  2. 排序半透明绘制项。普通 Alpha Blend 通常按从后往前排序。引擎常用物体中心、包围盒等生成排序键，因此只能近似代表整个物体的深度。
  3. 开启深度测试，通常关闭深度写入。用不透明深度剔除被墙体等挡住的透明片元，但透明片元之间不互相写深度遮挡。ShaderLab 中常见状态为 ZTest LEqual、ZWrite Off；在直接设置图形 API 状态时，深度比较方向还需匹配管线的深度约定，例如 Reversed-Z。
  4. 在透明材质的片元着色器里算光照。使用该片元自己的位置、法线和材质参数计算颜色，再交给混合单元与 SceneColor 合成。透明表面的材质数据通常不写进常规 GBuffer。

关闭深度写入是因为半透明表面后面的东西仍然应该贡献颜色；如果近处透明物体先写入深度，后画的远处透明片元会被直接剔除。关闭深度写入只避免这类错误遮挡，并不能自动解决透明排序。

透明着色也可以使用 Forward+ / Clustered 的灯光列表，减少每个片元需要遍历的光源数。但不能直接照搬只根据不透明表面深度范围裁剪出的灯光列表，否则可能漏掉只影响透明表面的灯；灯光剔除范围必须覆盖透明片元所在的空间。

普通 Alpha Blend 由硬件混合单元读取目标颜色，着色器不需要显式采样 SceneColor。折射、扭曲等效果才通常需要采样背景颜色，这时一般准备 SceneColor 副本或独立输入纹理，避免一边写渲染目标一边把同一资源当作普通纹理读取。只复制不透明背景时，多层玻璃之间的相互折射仍然是不完整的。

实际引擎还可能把透明物体画到单独的颜色 / 透射率缓冲中，在景深、色调映射等阶段前后再合成。具体插入位置取决于效果需求，但核心仍然是额外的透明着色与合成路径。UE 4.27 Deferred 的 Standard / AfterDOF / AfterDOFModulate 划分见 为什么要分成不同的半透明 Pass，颜色、透射率和滤色的合成见 独立半透明缓冲到底存了什么。

Alpha Test 是另一种情况：被丢弃的片元不写入，保留的片元当作不透明表面写 GBuffer 和深度，所以通常可以直接走延迟路径；它没有表达连续的半透明。

透明物体交叉如何处理 ​

为什么按物体排序会失效 ​

两个透明面片 A、B 相交时，屏幕左侧可能是 A 在 B 前面，右侧却是 B 在 A 前面：

text
左侧像素：相机 -> A -> B -> 背景，需要先 B 后 A
右侧像素：相机 -> B -> A -> 背景，需要先 A 后 B

此时不存在一个适用于整个物体的绘制顺序。按物体中心排序会让一部分像素出错，相机移动时还可能突然交换顺序。把排序细化到三角形可以改善一些情况，但相交三角形本身仍可能需要相反的局部顺序，多个面片也可能形成循环遮挡。

这是普通透明混合本身的问题，前向和延迟管线都会遇到。提高透明排序优先级只能强制指定整批物体的顺序；额外做一次透明深度预通道通常只保留最近的透明层，会漏掉后面的透明贡献，都不能通用地解决交叉问题。

方法一：拆分几何后排序 ​

沿交线切分面片，把局部前后关系不同的部分拆开，再按可排序的片段从后往前绘制。对于静态、数量少、交叉关系简单的模型，可以在制作阶段拆分，或采用 BSP 等空间划分方法。

代价是几何数量和管理成本增加；对于动态变形、粒子和频繁变化的交叉关系，实时求交与切分通常不划算。仅把模型随意分成几个子网格，并不保证消除所有交叉或循环遮挡。

方法二：OIT（Order Independent Transparency） ​

OIT 让最终结果不再依赖应用提交物体的先后顺序。它包含多种方法，其中一些仍会在像素内部排序，另一些则近似计算合成结果。

方法如何处理交叉主要代价与限制
Depth Peeling（深度剥离）第一轮取最近透明层，下一轮取上一层之后最近的一层，逐层提取并按正确顺序合成需要反复绘制；层数越多，开销越大；限定轮数会漏掉剩余层
A-buffer / PPLL（逐像素链表）为每个像素保存通过不透明深度测试的透明片元，包括深度、颜色和 alpha，随后逐像素排序并合成需要较多显存、原子操作和排序；片元缓冲或每像素容量不足时必须处理溢出
Weighted Blended OIT（加权混合）累积带权颜色与 alpha，同时累积透射率，最后近似合成；无需逐层排序存储相对固定，适合烟雾、粒子等；层次颜色是近似值，高 alpha、颜色差异大时误差更明显

Depth Peeling 在提取全部相关层、PPLL 在完整保存并正确排序全部相关片元时，可以得到标准 Alpha 合成意义下的正确结果。这里不包含多次折射、体积吸收等完整的光传输效果。

Weighted Blended OIT 的常见思路可以写成：

text
对通过不透明深度测试的每个透明片元 i：
    accum_rgb   += C_i * alpha_i * w_i
    accum_alpha += alpha_i * w_i
    revealage   *= (1 - alpha_i)

初始化：accum_rgb = 0，accum_alpha = 0，revealage = 1
合成：
    C_avg   = accum_rgb / max(accum_alpha, epsilon)
    C_final = C_avg * (1 - revealage) + C_opaque * revealage

其中 C_i 是未预乘的线性颜色，w_i 是通常与 alpha、深度有关的正权重，应根据实际深度约定调整。加法和乘法的累积在数学上与提交顺序无关，因此交叉物体不需要整物体排序。但这种方法没有保存每层的前后关系，C_avg 也不是严格按深度合成的颜色，所以它是近似 OIT；浮点运算还可能引入微小的顺序差异。

交叉处的硬边：Soft Particles ​

粒子面片插入地面、墙体等不透明物体时，深度测试会直接切掉被遮挡的部分，形成明显的交线。Soft Particles 通常采样场景深度，将两者转换到相同的线性视空间深度后，用间距衰减 alpha：

text
fade = saturate((scene_linear_depth - particle_linear_depth) / fade_distance)
alpha *= fade

这里约定线性深度沿远离相机方向增大，fade_distance > 0。粒子越接近不透明表面越透明，从而让交界柔和。它主要解决粒子与不透明表面的交线，不解决两个透明物体之间的排序，因为普通场景深度通常没有保存透明表面。

如何选择 ​

  • 普通少量玻璃：先使用前向透明 Pass、从后往前排序、深度测试开启且深度写入关闭；局部交叉可考虑拆分模型。
  • 大量烟雾、粒子：可以考虑 Weighted Blended OIT；与不透明场景相交处再配合 Soft Particles。
  • 必须准确表现多层遮挡的透明表面：考虑 Depth Peeling 或 PPLL，同时评估层数、显存和性能预算。
  • 栅栏、树叶等主要需要镂空轮廓的材质：优先考虑 Alpha Test；它不能替代玻璃这类真正的半透明。
  • UE 4.27 常规光栅路径中的排序策略，以及 Priority / Offset 的作用与限制，见 UE 半透明渲染：排序；该路径没有通用 OIT。
